# Race Passport and race-day tools

## Race Passport (`/passport`, `/passport/[id]`)

The passport is one place per race, for a HYD Runners event or any race elsewhere. Upcoming HYD Runners events the runner has a place at are offered in one click.

**Each race has:**

- a countdown;
- status (planning, registered, finished, did not finish, did not start, cancelled);
- target time, bib and wave;
- a logistics checklist: defaults per distance, and runners can tick, add and remove items;
- private travel notes;
- an emergency contact, validated and shown on the runner's own race-day screen;
- links to the race-prep training plan and the pacing calculator;
- the current race estimate, labelled as not a guarantee.

**For HYD Runners events, it also shows:**

- start time, meeting point, the runner's pace group and check-in status;
- the event page with route, elevation and updates;
- sponsors;
- a **QR check-in code**.

`race_entries` is owner-only: organisers never see entries. The emergency contact is never shared.

## Results and history

The source of every result is shown:

| Source                      | How it's set                                                                                                               |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Verified by the organiser   | From `event_results`. It always takes precedence, and runners can't set it.                                                |
| From your recorded activity | The runner picks one of their own race-day activities. The time is copied from it by the database, which checks ownership. |
| Entered by you              | Self-reported.                                                                                                             |

The history lists past entries plus any organiser results for events that aren't in the passport. A private reflection can be added to each race.

There are no photo uploads yet. Finish-line photos would need storage, moderation and consent from the people in them; this is recorded as not implemented on the roadmap.

## Race partners

- Opt-in per race ("Let other runners in this race with a similar target find me").
- `race_partners()` returns other opted-in runners in the same event, or the same external race name and date, at the same distance.
- Their target must be within 10%, or no target is set.
- Blocked runners are excluded both ways.
- Only name, target and fitness level are shown.

## QR check-in

- Every RSVP gets an unguessable `checkin_token`, always generated by the database (callers can't choose it).
- The passport shows it as a QR code linking to `/events/[id]/check-in?token=…`.
- Scanning it with any phone camera opens that page. Only the event's organisers, captains and sweepers can confirm (`check_in_by_token`). It reuses `check_in_attendee`, so check-in opens two hours before the start and closes a day after the end. Volunteers aren't check-in staff.

## Organiser tools (event → Manage → Race day)

| Tool           | What it does                                                                                                                                                       |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Attendance CSV | `/api/v1/events/[id]/attendance`, for the event team only, via `event_roster`. Cells are quoted, and spreadsheet formulas are neutralised.                         |
| Results import | Paste `user_id, outcome, time` lines (the CSV's columns). Each line goes through the same rules and RLS as single results. Invalid lines are reported and skipped. |
| Sponsors       | Organisers manage sponsors (name, https link, tier). They're shown on the passport, and links use `rel="sponsored"`.                                               |
| Volunteers     | A new team role. Organisers can add or remove volunteers and give each a task.                                                                                     |

Route uploads use the existing routes and GPX tools. Payments and ticketing stay disabled.
